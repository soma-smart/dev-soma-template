# Reviewing a PR — SOMA style

## Architecture

- [ ] No third-party imports under `src/<pkg>/domain/`.
- [ ] No `datetime.now()`, `uuid.uuid4()`, `random.*` calls in `domain/` or `application/` — abstractions used.
- [ ] No `float` for monetary or precise quantities in `domain/`.
- [ ] No log calls inside `domain/` or `application/`.
- [ ] No `infrastructure/` import from `presentation/` (concretes are injected via `Depends`).
- [ ] New `DomainError` subclass has an `ERROR_HTTP_MAPPING` entry.
- [ ] Naming follows `naming-conventions` (no `Manager`/`Helper`/`Service`, role stereotypes used).

## Tests

- [ ] Unit tests for new use cases / domain logic. Fakes only — no `unittest.mock` in `tests/unit/`.
- [ ] GIVEN/WHEN/THEN format: function name and body markers.
- [ ] Integration tests if a new infrastructure concrete was added.
- [ ] E2E tests: 1 happy + 1 critical-error per endpoint, no use case branch duplication.
- [ ] mutmut run on touched paths in `domain` + `application`.

## Migrations

- [ ] Autogenerated migration was read and curated.
- [ ] `downgrade()` is non-empty and round-trip tested.
- [ ] No destructive operation without explicit approval in the PR description.

## Helm (if `helm/` changed)

- [ ] Field present in both `values.yaml` and `values.schema.json`.
- [ ] Each environment overlay updated as needed.
- [ ] `helm lint` passes; `kubeconform` passes; `polaris audit` reviewed.

## Operational

- [ ] No secret in code, no `.env` committed.
- [ ] Conventional Commits messages.
- [ ] PR size manageable (<500 LOC). If larger, justify or split.
- [ ] CI is green: ci-quality, ci-security, ci-mutation, ci-helm (when applicable), ci-migration-drift (when applicable), ci-image-scan.

## Useful one-liners

```bash
git diff main...HEAD --name-only   # files in the PR
just lint                          # ruff + ty + custom architectural lints
just test-all                      # unit + integration + e2e
just mutate                        # mutation testing on domain + application
just helm-lint
```
